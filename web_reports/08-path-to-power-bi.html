Power BI is workflow step 04. It starts after Report 07 closes CDE setup, and after a raw copy, a clean layer, and a SQL model exist. The reporting source for this practice project is the Snowdon issue workbook, plus a Forma files export if the account can produce one.

2. Sequence

  1. Preserve raw inputs. After the document register exists, create snowdon_analytics/data/raw/ and copy the issue workbook there unchanged. If Forma exports a files log or an issues list, save that export beside it. Record file name, retrieval time, and source platform.
  2. Clean in Python, in a separate layer. Read the Issues sheet. Keep original columns in the raw layer. Add source_file, source_sheet, and ingestion_timestamp as ingestion metadata. Standardise dates, identifiers, and blanks only in the clean layer. Write failed rows to a rejection list. Load the Overview sheet on its own. It is a cover, not 289 issue facts.
  3. Check the raw file against Report 06 before modelling. Expect 289 issue rows, 289 unique IDs, status counts from Open 148 through In review 3, and the fill rates already recorded for due date, closed date, description, root cause, and location.
  4. Model only tables the columns can fill. See the table below. Skip review-event and version facts until an export contains those histories.
  5. Build Power BI on the SQL tables. Reconcile every published total to a SQL query and to the 289 source rows.

5. Measures that match this workbook

  • Total issues, and counts by the nine status labels.
  • Counts by category, type, assignee, and company.
  • Issues with a due date, and issues with a location.
  • Created-on trend after the Excel serials are converted and checked.

Closed and Completed are separate status labels (11 rows each). Closed at is filled on 14 rows, so a resolution-time measure waits until those two fields are defined against each other. The published overdue rule is on the lifecycle page.
