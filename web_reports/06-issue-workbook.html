How the workbook is produced

04_Reports/Snowden Towers Sample Issue Summary.xlsx is an issue-register export. The cover reads Sample Project, Issue summary, created by Jonathan Hand (Apex Program Management), 289 items. The steps below are the construction sequence. Each earlier step files a different folder. The workbook appears when the issue register is exported into 04_Reports.

StepWhat the project exports or filesFolder and file
−7. Project requirements and CDE setup No document is exported. Naming, metadata, permissions, user groups, and the controlled workflow are defined. The five type folders are created as the filing plan. 04_Reports is the folder reserved for this workbook, and it is empty here. 01_Design Files, 02_Drawings, 03_Models, 04_Reports, 05_Contracts
−6. Site planning and initial design Site context is established and design information starts. The chart names Forma Site Design as one place that work can happen. This package has no site-planning file. None of the 14 files
−5. Design work in progress The structural model is the authoring file. Sheet drawings are published from that design work into DWG and PDF. This sample holds those outputs under the same sheet numbers: S102, S103, S107, S108, S600. 03_Models: Snowdon Towers Sample Structural.rvt. 02_Drawings: five DWGs. 01_Design Files: five sheet PDFs and the multipage PDF.
−4. Shared for coordination and review The shared model and drawings are checked. Issues are raised in the CDE issue tool and stored against those files. The register is still inside the issue tool. No new file yet
Issue export, from the register at −4 The issue register is exported to Excel and filed in the reports folder. This is the action that produces the workbook. The filename spells Snowden. 04_Reports / Snowden Towers Sample Issue Summary.xlsx
Contract filing The executed subcontract is filed as its own controlled document. It does not generate the issue workbook. 05_Contracts / Executed Subcontract Agreement – Structural Steel Fabrication & Erection_0.docx
−3. Documents authorised for tender Authorised drawings and specifications are issued for procurement, under document control. The chart says this issue is for tender, and is not automatic authority for construction. 01_Design Files, the sheet PDFs
−2. Procurement package published Solicitation documents are released to bidders. The chart says a project CDE could support that preparation, and the USACE internal platform is unverified. No file in this Snowdon package
−1. Tender RFIs registered and answered Bidder questions are logged and answered. The chart says Forma Build is an illustration of that workflow, and is not a verified USACE source. A tender RFI register, separate from this issue summary
0. Public RFI register published as Excel The verified public file on the second chart is “RFI log for posting 9.23.26.xlsx”, issued with the procurement opportunity. That public RFI workbook. It is a different Excel file.
01. Raw RFI Excel data The public workbook is preserved, with its source lineage, as data/raw/rfi_log.xlsx. data/raw/rfi_log.xlsx, still the public RFI workbook

In this practice the fourteen files arrived together in Project Files_2026-10-13_01-27-04pm.zip. The workbook was already in 04_Reports. An issues export was not run on the Forma screen, and that folder’s file list was left closed.

Profile of the file on hand

Created on and Updated on are Excel date serials in the file (around 46237). The cleaning step will convert them. This report leaves the raw values unchanged.
